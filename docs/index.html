migrateme.tech

Open-source, AI-assisted CMS migrations — dry-run first, so you see exactly what moves before anything does.

What it does

Migrating a site between platforms usually means hand-written scripts, silent data loss, and no way to rehearse. migrateme.tech treats a migration as a pipeline you can inspect: extract, map, rehearse with a full dry-run risk report, approve, execute with checkpoints, then validate with a reconciliation report.

  • MVP path: WordPress (WXR export) → Markdown / MDX
  • One core engine, three surfaces: CLI, MCP server, and web
  • AI field mapping with strict output validation — deterministic rules first, AI only where fields get messy
  • Safe by default: dry-run before execution, checkpointed runs with resume, idempotent writes

Proof, not promises

On October 14, 2026 the toolkit ran against a real WordPress site — not a fixture. The source is DXS, a purpose-built WordPress testbed; its live export went through the full pipeline: plan, dry run, approved migration, validation.

  • 44 items migrated — posts (incl. draft, private, and scheduled), pages, attachments, plus the site's templates, navigation, global styles, and even its AI Guidelines
  • 420 field mappings — 287 deterministic, 133 held for human review rather than guessed
  • 310 risks flagged in the plan; zero files written by the dry run
  • Validation passed: 44 expected, 44 found, empty exception queue

How it's paid for

Freemium, with a donation bundle instead of a paywall. The toolkit is free and MIT-licensed, and the AI step runs a local open-weight model, so a migration costs nothing to run — that's what makes freemium honest here rather than a trial in disguise.

When a migration succeeds, the tool inventories the open-source technology it touched: the platform the site came from, the platform it's going to, and the open-source stack the tool itself stands on. Where a project has an open-source foundation behind it (the WordPress Foundation is the model), the tool assembles a suggested donation across all three directions — source, destination, and the conversion itself. A Humble Bundle–style slider lets you set the amount and choose the split: how much supports this tool, and how much flows to the foundations and libraries that made the original site, the move, and the new site possible.

Designed, not yet wired: the MVP ships the migration pipeline; the donation bundle is the business model it will grow into, because a tool that moves people between open-source platforms should feed the commons it depends on.
